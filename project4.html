CS 180 Project 4

Image Warping and Mosaicing · Kavish Kondap

Overview

In this part, I recover homographies from corresponding points, use inverse warping to rectify images, and blend overlapping photos into mosaics. I implement nearest neighbor and bilinear interpolation and compare their results.

A.1: Shoot the Pictures

I use six sets of three overlapping photos: a gate, a sculpture, a street intersection, a living room, a vertical portrait, and a cathedral interior from OpenCV’s stitching test data. Each set shows the same scene from different directions. It's important to keep the COP of the camera still while rotating, especially for scenes with objects with different depths, since this prevents parallax/warping effects. The source images are shown with each mosaic in A.4. I took photos on my iPhone 16 Plus, and resize the mosaic inputs to a maximum dimension of 1400 pixels before selecting points and warping. The two rectification inputs are 768 × 1024.

A.2: Recover Homographies

A homography maps a point in one image to a point in another. I choose to use the (row, column) convention rather than the (x, y) convention and set the bottom-right entry of H, the transformation matrix, to 1, leaving eight unknowns. After multiplying by H, I divide the first two coordinates of the output pose vector by the third to normalize.

[ r′ ]         [ h1  h2  h3 ] [ r ]
[ c′ ] ∼ H p = [ h4  h5  h6 ] [ c ]
[  1 ]         [ h7  h8   1 ] [ 1 ]

Rearranging the two coordinate equations gives two linear equations for each correspondence. I stack all the row equations followed by all the column equations, then solve Ah = b with np.linalg.lstsq.

[ r  c  1  0  0  0  −rr′  −cr′ ] h = r′
[ 0  0  0  r  c  1  −rc′  −cc′ ] h = c′

h = [h1, h2, h3, h4, h5, h6, h7, h8]ᵀ

Four pairs are enough to solve for H, but more points make the estimate less sensitive to individual errors. For these mosaics, I use 12 pairs spread across each overlap. The numbered correspondences and recovered matrices are shown with each result below.

A.3: Warp the Images

In order to determine the size of the output image, I first transform the image corners to find the output bounds, then create a grid over that region. For each output pixel, I apply H−1 to find the corresponding position in the input. This inverse mapping avoids the holes that forward warping can leave. Positions outside the input image are filled with zeros.

Interpolation

Nearest neighbor rounds the input coordinates to the closest pixel. Bilinear interpolation takes a weighted average of the four surrounding pixels. If a and b are the fractional parts of the row and column coordinates, the weights are:

(1 − a)(1 − b),   a(1 − b),   (1 − a)b,   ab

Rectification

I select the four corners of each object in top-left, top-right, bottom-right, bottom-left order and map them to a rectangle. I use 600 × 400 for the sign and 400 × 600 for the framed drawing. I warp the region around each object and crop the result to the target rectangle.

A.4: Blend the Images into a Mosaic

I keep the middle photo as the reference and transform the two outer photos into its coordinate system. I use the transformed image corners to find a shared canvas and place each warped image at its corresponding offset.

To blend the overlap, I give each input pixel a weight based on its distance from the nearest image edge. I warp these weights with the same homography as the image, then divide the weighted sum of the images by the sum of the weights. The masks are separate from the image values, so black pixels in a photo are kept. Pixels with no coverage remain black.

I(p) = ∑i wi(p)Ii(p) / ∑i wi(p)

Portrait

For this set, I combine three vertically overlapping photos of my friend. I keep the torso image as the reference and warp the upper and lower views into it. The result includes his head and feet in one image. The shirt mostly lines up, but there is some ghosting near the neckline and arms. The door frame also changes direction between views, showing that the whole scene is not aligned exactly.
